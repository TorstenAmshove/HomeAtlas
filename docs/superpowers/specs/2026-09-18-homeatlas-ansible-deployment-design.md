# HomeAtlas Ansible Deployment Design

**Goal:** Deploy HomeAtlas reproducibly on `docker.lan` through the existing Portainer and Traefik infrastructure without degrading LAN discovery.

## Architecture

HomeAtlas keeps its two-service layout. The backend and frontend run in Docker host-network mode because backend discovery must read the host ARP table and send mDNS/SSDP multicast. The backend remains bound to `127.0.0.1:8281`; the frontend serves the UI on `0.0.0.0:8280` and proxies API and WebSocket requests to the loopback backend.

Traefik stays on its existing bridge-network deployment and uses a file-provider route to forward `https://homeatlas.malt10.de` to `http://192.168.42.20:8280`. HomeAtlas does not join Traefik's `proxy` network because Docker bridge networking would prevent correct LAN discovery.

## Image Delivery

GitHub Actions builds and publishes separate public GHCR images from the HomeAtlas repository:

- `ghcr.io/torstenamshove/homeatlas-backend:sha-<40-character-commit>`
- `ghcr.io/torstenamshove/homeatlas-frontend:sha-<40-character-commit>`

Only commit-derived tags are published. The Ansible stack requires such a tag explicitly, so a deployment is tied to one immutable source revision. The workflow runs after pushes to `master` and can be dispatched manually from another ref for the first deployment.

## Ansible Stack

`ansible-docker.lan` gets a `stack_homeatlas` role. It creates `/opt/homeatlas` with mode `0700`, deploys a Portainer Git stack using the GHCR images, and registers Uptime Kuma checks. The backend bind-mounts that directory at `/data`, preserving its SQLite database, Fernet key, and OUI cache. It mounts `/var/run/docker.sock` for existing Docker discovery and administration features.

The role requires `homeatlas_image_tag`, validated as a full commit-based GHCR tag. It uses the established `amshove.portainer_stack.stack_create` role and does not add registry credentials because the HomeAtlas repository and images are public.

## Security and Operations

The backend is never reachable through Traefik or a host interface. The frontend remains directly reachable at `http://192.168.42.20:8280`; network firewalling is a separate host policy if HTTPS-only access is required. HomeAtlas can control Docker through the mounted socket, so the HTTPS route is intended only for the LAN or WireGuard access paths already used by this environment.

The first administrator password is generated by HomeAtlas unless users are preseeded. It is intentionally not stored in Ansible Vault. Backups must include all files in `/opt/homeatlas`, particularly `homeatlas.db` and `secret.key` together.

## Verification

The implementation validates the HomeAtlas frontend with `npm run build`, Python modules with `python3 -m compileall -q backend/app`, Compose configuration with `docker compose config --quiet`, and Ansible syntax with `ansible-playbook --syntax-check`. After deployment, verify the backend health endpoint locally, the HTTPS route and WebSocket UI externally, and a scan of `192.168.42.0/24`. Additional VLANs are configured as scan subnets in HomeAtlas; ARP and multicast remain limited to the directly attached VLAN 42.
